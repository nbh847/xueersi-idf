# Launcher 电池电量显示设计

状态：暂缓，不实施。2026-10-01 用户决定保留 Launcher 左上角 `Xiaomiao`，不替换为电量或 `--%`。现有调研与候选方案保留供未来参考；恢复开发需用户重新明确要求，真实数据源与实板仍未验证。

## 目标与范围

原候选方案是删除 Launcher 左上角的 `Xiaomiao` 品牌文字，在同一区域显示电池图标与剩余电量，仅覆盖 Launcher。该方案现已暂缓，左上角保持原样。下文显示规则、实现路径与验收清单均为保留方案，不属于当前开发计划；本次只记录决定，不修改固件。

## 数据获取结论

**按仓库现有原理图与源码，原厂机器没有已确认的软件电量读取通道，不能承诺纯固件显示真实百分比。** 以下结论来自仓库静态资料，并非实板测量：

| 证据 | 核对结果 | 含义 |
| --- | --- | --- |
| `xueersi-xiaomiao-schematic.pdf`，V1.0／P1，右上供电与右侧充电区域 | 电池 `BAT+` 经 D3、SW1 接至 Q2 稳压器输入，Q2 输出 `VCC`；图中未见电池分压接到 ESP32 或 GD32 的 ADC | MCU 无已确认的电池电压采样点 |
| 同页 U9 | 标注 `TP4056X-435-ESOP8`；`CHRG#`、`STDBY#` 分别接 LED4、LED3，图中未见连接 MCU，也未标注 I2C／数字电量接口 | 不能从现有固件直接读出充电状态或百分比 |
| 同页 U2／U1 | ESP32 的 GPIO36／39 接光照／热敏，GPIO32／33 为扩展输入；未见 `BAT+` 采样连接；GD32 的 PA9 经 R16 接 `VBUS` | `VBUS` 线路不等于电池采样，也不能据此断言正在充电 |
| `main/main.c` | ADC1 只配置通道 0、3、4、5，分别读取光照、热敏、GPIO32、GPIO33；未实现电池采样或电量估算 | 不能把现有 ADC 百分比直接当作电量 |
| `README.md`、`GD32_firmware/Project/src/` | 已记录的 `0x40` 协议是 LED／电机控制；仓库 GD32 源码没有电池读取接口，且实际板载固件与仓库源码对应关系待查 | 不能猜测电量寄存器或擅自更新 GD32 固件 |

原理图是第三方整理资料，可能与实板存在差异，因此准确表述是“现有资料不支持读取”，而不是声称已经对所有硬件版本证明不可读取。若原厂运行环境存在电量 API，后续必须追踪其真实数据来源并核对实板连接，不能只凭 API 名称判断可用。

项目默认面向原厂硬件。增加电池分压或电量计属于另行授权的硬件改动，不纳入本设计，也不把硬件改造作为当前功能可实现的前提。

## 显示规则

- 布局以现有标题起点 `x=5、y=2` 为基准，电池图标约 18 × 10 px，右侧使用 12 px 字体显示 `85%`；总宽度暂定不超过 65 px，底边不得进入 `y=19` 开始的卡片区。数字行高按实际字体复核，不机械复用现有 14 px 标题框。
- 图标使用 LVGL 基础图形绘制，不依赖图片资源、SD 或新增第三方组件。
- 有合法、未过期且经过验证的数据源时显示 `0%`～`100%`，图标填充与数字一致；`0%` 是有效值。
- 没有数据源、首次采样尚未完成、采样失败、数据非法或过期时，显示空心电池轮廓与 `--%`，内部不画电量填充。空心轮廓配合 `--%` 表示未知，不表示电池耗尽。
- 电量不高于 20% 时使用告警色，但必须同时保留数字；未知状态使用中性色。不显示虚假的 `100%`，不根据开机时间、USB 插入或传感器读数推算电量。
- 充电闪电标识只在有独立、可信的充电状态来源时显示。当前无该来源，首版不显示闪电，不将 USB 供电解释成正在充电。
- 中文与英文回退均显示同样的图标、数字和 `%`。Launcher 两页位置一致，进入 App 后随 Launcher 隐藏；返回时读取最新快照。

当前硬件条件下实施此 UI，只能显示 `--%`，不能达到“真实电量”验收。该降级应在功能实施前明确接受，不能将占位显示记为电量采集完成。

## 后续实现路径

1. 先确认数据源：取得实板连线证据或可核对的原厂固件读取实现。确认采样引脚、量程、分压、共享资源、充电状态来源以及电池规格；未确认前不新增 ADC 通道、不探写 GD32 寄存器。
2. 无数据源时，若继续实施 UI，仅在 `main/framework/xiaomiao_launcher.c` 替换标题为未知电量组件，不增加空转采样任务或无用 Service。
3. 有数据源后，采集与估算由 `main/services/` 的 Battery Service 负责，Launcher 只读快照。快照至少区分电压有效性、百分比有效性、采样时间和充电状态是否已知；只有电压时不能自动声称百分比有效。
4. 若实际来源是 ADC，沿用现有 ADC1 所有权并协调访问，禁止为同一 ADC unit 重复初始化。电压需校准并还原分压，百分比需依据已确认电池规格和放电曲线标定，不能直接采用未经核对的固定满电电压或线性映射。采样周期、滤波和过期阈值在数据源确认后确定。
5. LVGL 对象只在 UI 线程更新；Launcher 销毁时先删除刷新 timer 再删除对象，反复进入／退出不累积对象。

## 验收与未验证范围

文档验收：核对标题位置、ADC 配置和原理图完整页面；检查文档链接及 `git diff --check`。本次不需要固件编译，也不执行烧录或串口操作。

未来固件实施由人工运行 `idf.py build`，或 `idf.py -p COM5 flash monitor`（串口按实际设备替换）。检查两页 Launcher 的 `--%`、`0%`、`20%`、`100%` 排版、中英文回退、右上 Wi-Fi、卡片导航及五 App 往返；注入非法／过期快照确认恢复 `--%`。若接入真实来源，还需人工对照测量仪器验证电压、插拔 USB、充放电与电量变化，并覆盖读取失败及恢复。

未验证：实板是否存在原理图未收录的采样连接；原厂或当前板载 GD32 是否另有只读接口；电池规格与百分比曲线；UI 实机渲染。没有这些证据前，功能状态保持“数据源待确认／固件未实施”。
