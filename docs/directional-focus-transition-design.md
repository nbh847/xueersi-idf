# 方向键选项切换动效设计

状态：候选方案待选择；仅文档，未修改固件，未构建或实机验证。2026-09-27 19:29。

## 目标与范围

使用方向键改变**选项焦点**时，增加短促、清楚的视觉过渡，让用户看见焦点从哪里移到哪里。逻辑选中项仍在按键被接受时立即更新，A 键总是打开最新焦点对应的项，不等待动画结束。动效不改变页面结构、按键映射或持久化配置。

首批适用位置：Launcher 的四向焦点移动，以及 Settings 当前顶层菜单、Wi-Fi 可操作项的上下移动。若 [Tools／Settings 归位设计](launcher-tools-settings-reorganization-design.md) 落地，Settings 新增的 System 子菜单和 Wi-Fi 连接详情可按同一规则接入；Tools 仅有一个番茄时钟入口时没有可切换的菜单选项。番茄时钟内部的操作项焦点由 [番茄时钟设计](pomodoro-timer-design.md) 单独验收。各 App 中“左／右切换数据页”及 Hardware Test 的 15 页切换属于**整页导航**，不是选项焦点移动；本设计暂不改变其翻页效果，避免把两类交互混在一次施工中。

## 当前实现与约束

- `main/framework/xiaomiao_launcher.c` 用注册索引表示焦点。同页移动只改变旧卡片与新卡片的蓝色背景、白色边框；跨页移动会重新填充四个固定卡片对象，然后更新页码。
- `main/apps/settings/xiaomiao_settings.c` 与现有 `main/apps/tools/xiaomiao_tools.c` 都由页面根对象接收按键，菜单行只是装饰对象。Settings 顶层与 Wi-Fi 操作项目前直接切换蓝底、白框。后续页面归位后 Tools 将无可选菜单。
- 屏幕为 160 × 128 ST7735，当前为单块 40,960 字节全屏 DMA 缓冲，LVGL 任务目标刷新周期 16 ms；连续全屏变化的效果可能放大刷新与 SPI 压力。动画应主要影响焦点附近的小区域，不增加全屏缓冲或新任务。
- 当前焦点样式是辨识选项的主要方式。动效结束后仍需落到相同的高对比蓝底、白框静态状态，不能只靠动画颜色表达焦点。

## 候选效果

下表的时长和位移是**设计初值**，用于比较与实机试调，并非当前固件性能实测值。最终只选一种主效果；若想组合，也需先确认具体组合，避免多层效果叠加后过亮或拖慢输入。

| 编号 | 效果 | 视觉过程 | 建议时长 | 特点与代价 |
| --- | --- | --- | --- | --- |
| A | 焦框滑移 | 旧项蓝底立即退回普通状态，一条白色圆角焦框沿按键方向滑到新项；抵达后新项蓝底点亮 | 140～180 ms | 方向感最明确，适合 Launcher 和竖排菜单；需要一个独立焦框覆盖对象，跨页时须处理目标重建 |
| B | 光带扫入 | 新项从靠近旧项的一侧出现窄亮带，亮带横扫新项后留下完整蓝底和白框；旧项同步退亮 | 110～160 ms | 观感干净，焦点位置很快明确；需要限制亮带只在新卡片或菜单行内，不做全屏闪光 |
| C | 轻微缩放弹性 | 新项先轻微缩小或放大（约 3%），快速回到原尺寸；边框同步由淡到亮，旧项退亮 | 130～190 ms | 有“按下去再弹起”的手感，焦点不跨卡片移动；160 × 128 下要防止文字抖动和边缘裁剪 |
| D | 柔和光晕 | 新项边框由暗到亮并短暂出现一圈低透明度光晕，再收敛为正常边框；旧项退亮 | 120～180 ms | 稳重、实现区域小；方向感弱，若需要更明显的切换过程可考虑 A 或 B |
| E | 方向拖尾 | 从旧焦点到新焦点出现一段细短线／粒子拖尾，迅速消散，新项同时点亮 | 160～220 ms | 最有动感；需要额外临时图形，跨页和连续按键的清理更复杂，优先级低于 A～D |

建议第一轮先用 A、B、D 中的一种制作实机样例，再按目标板视频选定。C、E 可作为更活泼的备选。该建议只是施工顺序，**不代表已选定最终效果**。

## 统一交互规则

1. **只在焦点实际变化时播放。** 到达行／页边界、目标项不存在或方向键在当前页面无作用时，维持原样，不空播一次动画。
2. **输入先于动画。** 按键事件立即更新逻辑焦点和可操作目标；动画只渲染从旧位置到新位置的过渡。动画进行中按 A，直接打开最新焦点项，页面销毁前先停止相关动画并清理临时对象。
3. **连续按键可打断。** 再次按方向键时停止上一段过渡，从当前可见位置过渡到新目标，或在复杂效果下直接收敛到新目标再启动；不得排队导致视觉落后于逻辑焦点。短时间快速按键后最终静态焦点必须与逻辑索引一致。
4. **跨页单独处理。** Launcher 翻页时旧卡片与目标卡片不同时存在于同一页；先确定目标索引并更新页内容，再在新页目标卡片播放该效果的“进入”版本。页码立即更新。不把旧页卡片动画到屏幕外，也不影响现有同一行优先、缺行回退规则。
5. **亮屏恢复无补播。** 从黑底待机画面唤醒时显示当前稳定焦点；用于唤醒且被吞掉的方向键不启动动效。进入／退出 App、打开详情页、B 返回也不自动播放方向键焦点动效。
6. **弱化失败路径。** LVGL 临时对象分配失败或设备负载过高时，立即显示正确的静态焦点，按键仍可用。切换页面、关闭 App 或删除菜单时清理动画，不能回调已删除对象。

## 代码落点与施工方式

最终选择前不确定是否值得做公共动效模块。首版优先在 `main/framework/xiaomiao_launcher.c` 实现选定效果并用真实按键检查观感；确定视觉语义后，再在 `main/apps/settings/xiaomiao_settings.c` 的顶层与 Wi-Fi 行复用必要的少量逻辑。若跨多个页面确实出现重复，再提取最小共享函数。动画使用项目已引入的 LVGL 9.5 能力，在 LVGL 任务中执行，不新开 FreeRTOS 任务、不加入第三方动画库、不改实体键去抖或全局按键时序。效果选定后再确定具体 LVGL API 与参数，并以本机组件源码核对版本兼容性。

可按两个检查点实施：

| 检查点 | 交付与静态检查 | 人工验收 |
| --- | --- | --- |
| CP1 Launcher 样例 | 同页四向、跨页进入、快速连按、A 中断、B 返回的焦点一致性；对象删除路径和 `git diff --check` | 目标板录制短视频对比静态基线与所选效果；检查五 App 入口、页码和翻页焦点 |
| CP2 Settings 接入 | 顶层与 Wi-Fi 菜单只在真实移动时触发；页面切换、配网、关闭时清理动画 | 目标板检查四项菜单与 Wi-Fi 操作项快速连按、A／B 中断、中文和英文显示；观察串口无新增错误 |

固件编译、烧录和目标板操作按项目 `AGENTS.md` 由人工执行。可用 `idf.py build` 或 `idf.py -p COM5 flash monitor`；Agent 只复核源码、diff 和人工提供的视频／日志。动效是否“好看”以用户在实机视频中的选择为准；没有实机证据时不写“流畅”“无闪烁”或“验收通过”。
