## 目标与预期行为

新增独立的 `PC Monitor` App，并通过统一 App Registry 注册到普通固件。Launcher 按 Games → PC Monitor → Hardware Test 顺序显示 3 个入口；用户按 A 进入 PC Monitor，页面显示 CPU、RAM、GPU 和 TEMP 四项指标，无数据时各指标值统一显示 `--`，百分比和温度单位分别显示 `%` 与 `°C`；短按 B 返回 Launcher。

本节点只交付可进入、可返回、可稳定重复创建与销毁的静态 UI 骨架，为节点 11 接入真实 PC 数据保留明确页面位置。不得提前实现 PC 端采集、通信协议、Wi-Fi、后台接收、定时刷新或动态数据接口。

## 背景与文件入口

- `docs/xiaomiao_firmware_v0.1_design.md` 第 6 节定义 PC Monitor v0.1 页面包含 CPU、RAM、GPU、TEMP 四项，无数据时显示 `--`；第 15 节把它列为节点 6，真实通信列为节点 11。
- `main/apps/games/xiaomiao_games.{h,c}` 是当前独立业务 App 范例：静态 `xiaomiao_app_t` 描述、Navigation 内容根、无输入 group、短按 B 由 Launcher 转发、`close` 只清空对象引用。
- `main/main.c` 的 `launcher_boot()` 当前按 Games → Hardware Test 注册 2 个 App，注册顺序就是 Launcher 枚举和显示顺序。
- `main/framework/xiaomiao_launcher.c` 每页固定 2 列 × 2 行、最多显示 4 个入口；3 个 App 均位于第 1 页，不触发分页切换。
- `main/framework/xiaomiao_navigation.c` 在 App `open` 前创建内容根，在 App `close` 后统一删除内容根及全部子对象。
- `main/CMakeLists.txt` 通过 `APP_SRCS` 收集业务 App 源文件，`main/` 已在 include 路径中。

## 已确定的实现决策

1. PC Monitor 放在 `main/apps/pc_monitor/`，沿用节点 5 已确立的独立业务 App 目录结构，不把页面实现写入 `main/main.c`。
2. `xiaomiao_pc_monitor.c` 内定义固件全生命周期有效的 `static const xiaomiao_app_t` 描述；头文件只暴露 `const xiaomiao_app_t *xiaomiao_pc_monitor_app(void)`，不暴露 LVGL 对象或生命周期回调。
3. App 描述固定为 `id = "pc_monitor"`、`name = "PC Monitor"`、`icon = LV_SYMBOL_EYE_OPEN`、`init = NULL`。眼睛图标只表达“监控”，不使用 Wi-Fi 图标暗示本节点已经联网。
4. 普通固件注册顺序固定为 Games 第一、PC Monitor 第二、Hardware Test 第三。任一注册失败都记录 App ID 与错误码并终止后续 Manager／Launcher 初始化，不跳过失败 App，也不回退到旧 Dashboard。
5. PC Monitor `open` 只在 `xiaomiao_navigation_app_root()` 下创建一个全屏容器，不创建、切换或删除全局 screen，也不删除 Navigation 内容根。
6. 页面适配 160 × 128：顶部显示 `PC Monitor`；中部按 CPU、RAM、GPU、TEMP 四行排列；左列为名称，右列分别为 `-- %`、`-- %`、`-- %`、`-- °C`；底部显示 `B Back`。名称和值使用独立标签和固定列宽，禁止依赖空格在比例字体下模拟对齐。
7. 所有指标值均为编译期静态占位文本。不得从 ESP32 系统 API 读取数据，不保留未来协议结构，不为节点 11 预设未经确认的数据类型、刷新周期或错误状态。
8. 页面使用 LVGL 内置 Montserrat 字体、颜色和 symbol，不依赖外部资源。`°C` 必须在实机确认字形可显示；若出现缺字，不得静默交付或擅自改为其他含义，先记录证据并修订显示方案。
9. PC Monitor 不向 LVGL group 添加对象，也不注册按键事件。Launcher 根对象继续持有焦点：App 打开期间方向键和 A 被 Launcher 忽略，短按 B 经现有 `launcher_go_back()` 返回。
10. `close` 不调用 `lv_obj_delete()`，只清空自身对象引用并记录关闭日志。Navigation 在回调返回后删除内容根及全部子对象。
11. App 不创建 timer、event、Task、动态业务状态或非 LVGL 资源。每次 `open` 创建全新页面，不复用上一次已删除的对象引用。
12. Navigation 内容根为空时记录错误，不在活动 screen 上另建页面绕过 Navigation。现有 `void open(void)` 接口不为节点 6 扩展错误返回机制。
13. `open`／`close` 日志记录活动 screen 子对象数量。`close` 日志发生在 Navigation 删除内容根之前，跨轮次是否泄漏以每次 `open` 的稳定值和下一轮进入为准。
14. 三入口索引固定为 Games 0、PC Monitor 1、Hardware Test 2，页码均为 0。PC Monitor 返回后必须保持焦点索引 1；Hardware Test 返回后必须保持索引 2。
15. 节点 1～3 的三个 self-test 构建不注册真实 PC Monitor App，继续使用各自测试数据；普通固件才注册 Games、PC Monitor 与 Hardware Test。
16. ESP-IDF 编译、`set-target`、烧录、串口监视和目标板按键／显示验证全部由人工执行。Agent 只实施源码与文档修改、执行静态检查、提供命令并复核人工证据。

## 预期接口与生命周期

```c
#pragma once

#include "framework/xiaomiao_app.h"

const xiaomiao_app_t *xiaomiao_pc_monitor_app(void);
```

- 返回值始终指向同一个静态描述，不分配内存，调用方不得修改或释放。
- `open` 取得 Navigation 内容根，拒绝重复创建，在其下创建容器、标题、四行指标和返回提示；不调用 group 或 input API。
- `close` 允许在未创建或部分创建状态下调用，不删除 Navigation 内容根，只清空全部 PC Monitor 对象引用。
- 本节点不提供 `set_metrics`、`update`、`connect` 或其他数据接口；节点 11 应依据届时确定的通信与并发模型另行设计。

## 失败路径与处理要求

- PC Monitor 描述为空、ID 重复或注册失败：不得在缺失 PC Monitor 的情况下继续作为成功启动；记录 App ID 和错误码，保持节点未完成。
- 注册顺序不是 Games → PC Monitor → Hardware Test：修正 Registry 顺序，不在 Launcher 内增加排序规则。
- Navigation 内容根为空：不得改用 `lv_screen_active()` 创建页面；记录错误并保留 B 返回能力。
- 任一指标显示真实 ESP32 数据、随机值、`0` 或空字符串：视为超出范围或错误占位，恢复为 `--`。
- `%`、`°C` 缺失，`°` 字形显示异常，或名称和值无法对齐：视为 UI 验收失败，保持节点未完成并根据实机证据修正布局／字体方案。
- PC Monitor 新增 group 对象或抢占焦点：会绕开本节点复用的 Launcher B 分支，视为范围偏离，除非出现有证据的 LVGL 限制并先修订 Goal。
- PC Monitor 内方向键或 A 移动 Launcher 焦点、重新打开 App 或改变页面：视为输入隔离失败。
- 短按 B 无法返回、触发两次 close 或需要长按：视为返回失败，不复用 Hardware Test 状态机绕过。
- 增加第 3 个入口后焦点越界、PC Monitor 下键不能到 Hardware Test、Hardware Test 上键不能到 Games，或返回后焦点索引改变：视为阻塞性 Launcher 回归，不在 App 内手动重设索引掩盖。
- Hardware Test 短按 B 变为返回或长按 B 失效：视为阻塞性回归，恢复基于焦点的输入互斥。
- 多轮后 screen 子对象数量增长、重复日志、崩溃或花屏：保持节点未完成，定位内容根、引用清理或重复创建问题。
- 人工无法完成编译、烧录或实机验证：只记录静态结果，对应项标记“未验证”，不得将节点 6 标记完成。
