- 后续目标：节点 4“Hardware Test App”

## 目标与预期行为

在现有 App Registry、Manager 和 Navigation 之上实现适配 160 × 128 屏幕的 Launcher。Launcher 从 Registry 动态生成两列应用入口，支持方向键焦点移动、基础分页、A 键打开当前 App，以及 App 返回后恢复原页码和焦点。

本 Goal 只建立 Launcher 本体及其开发自测，不迁移现有 15 页 Hardware Dashboard，也不实现 Games、PC Monitor、Tools、Settings 或 Hardware Test 等正式业务 App。为避免节点 3 与节点 4 之间出现现有功能不可达的回退，普通固件在本节点继续直接启动 Dashboard；节点 4 将 Dashboard 封装为 Hardware Test App 后，再把普通固件默认入口切换为 Launcher。该过渡方案是对设计文档“节点 3 开机默认进入 Launcher”的有意拆分，最终 v0.1 验收要求不变。

## 已确定的实现决策

1. Launcher 放在 `main/framework/`，继续属于现有 `main` 组件，不创建新的顶层组件。
2. Launcher 不维护 App 列表副本；创建界面时按 Registry 注册顺序读取描述。Registry 在 Manager 初始化前完成注册，Launcher 运行期间不支持增删 App。
3. 每页固定显示 4 个入口，布局为 2 列 × 2 行。Registry 索引决定稳定显示顺序，页码由 `focused_index / 4` 推导；最多支持现有容量对应的 4 页。
4. Launcher 只保存自身 UI 根对象、LVGL group、当前焦点索引和必要的页面对象引用，不复制 Manager 当前 App 状态。
5. 左右键只在同一行相邻入口间移动，行首／行尾不循环；上下键按同列移动 2 个索引并可自然跨页。目标行只有左列入口时，从右列向下移动落到该行最后一个有效入口；其他越界移动保持原焦点。
6. 焦点移动后只重绘受影响入口和页码，不销毁并重建整个 Launcher。焦点必须同时有颜色、边框或反白等清晰视觉反馈，不只依赖难以辨认的细微颜色变化。
7. A 键调用 `xiaomiao_navigation_open()` 打开当前焦点 App，不直接调用 Manager 生命周期。打开失败时 Launcher 保持原页码、焦点和对象状态，并输出包含 App ID 与错误码的日志。
8. Launcher 根对象保留在活动 screen 上；Navigation 创建的 App 内容根覆盖其上。App 返回并删除内容根后，Launcher 仍保持进入前的页码和焦点，不重新注册 App、不重建整页。
9. B 键在 Launcher 根页面调用 Navigation 的幂等返回语义或直接保持不变，不改变焦点、页码和对象数量。自测 App 内的 B 键必须经 `xiaomiao_navigation_back()` 返回 Launcher。
10. Registry 为空时显示明确的空状态，不创建伪 App；方向键、A 和 B 均不得崩溃、越界或创建 Navigation 内容根。
11. App 名称来自 `xiaomiao_app_t.name`。`icon` 非空时可作为文本／LVGL symbol 显示；为空时使用统一、无外部资源依赖的占位表现，不为节点 3 引入 Assets 系统。
12. Launcher UI 与输入处理仅在现有 LVGL Task 中运行，不实现线程安全。所有 Launcher 对象都归 Launcher 根对象所有，销毁根对象必须释放全部子对象并从 group 中移除。
13. Launcher 自测使用独立 CMake 选项 `XIAOMIAO_LAUNCHER_SELF_TEST=ON`，默认关闭。该形态与 Framework、Navigation 自测及普通 Dashboard 启动路径必须通过 `#if / #elif / #else` 互斥。
14. 自测构建注册至少 7 个静态测试 App，以覆盖两页、偶数行和末页单项；测试 App 只创建最小内容和 B 返回路径，不进入普通固件。
15. ESP-IDF 编译、`set-target`、烧录、串口监视和目标板按键／显示验证全部由人工执行。Agent 只提供命令、执行源码与 diff 静态检查，并复核人工提交的输出和结果。

## 预期接口语义

接口命名可在实现时按现有风格微调，但必须保持职责最小且可验证：

```c
esp_err_t xiaomiao_launcher_create(lv_group_t *group);
esp_err_t xiaomiao_launcher_destroy(void);
size_t xiaomiao_launcher_focused_index(void);
size_t xiaomiao_launcher_page_index(void);
```

- `create(NULL)`：返回 `ESP_ERR_INVALID_ARG`，不创建对象。
- 首次 `create(group)`：按当前 Registry 创建 Launcher；空 Registry 也返回 `ESP_OK` 并显示空状态。
- Launcher 已存在时再次 `create()`：返回 `ESP_ERR_INVALID_STATE`，不重复创建对象或事件。
- `destroy()`：仅允许当前无 App 打开时执行；删除 Launcher 根对象及全部子对象并重置内部状态。未创建时调用保持幂等并返回 `ESP_OK`。
- App 打开期间调用 `destroy()`：返回 `ESP_ERR_INVALID_STATE`，Launcher 与当前 App 均保持不变。
- 焦点和页码查询在 Launcher 未创建或 Registry 为空时返回 0；实现不得返回越界索引。
- 输入事件回调必须只调用可独立测试的焦点移动／激活逻辑，避免把状态变更散落在 UI 绘制代码中。

## 执行检查点

### 检查点 1：Launcher 接口、状态与对象所有权

- 定义 Launcher 创建、销毁、状态查询和调用线程约束。
- 明确 Registry、Launcher、Navigation 和 App 的状态及 LVGL 对象边界。
- 创建独立 Launcher 根对象，确保全部卡片、标题、页码和空状态均为其子对象。
- 覆盖空 group、重复创建、重复销毁和 App 打开期间销毁等失败路径。

预期结果：Launcher 状态单一、生命周期确定，节点 4 只需注册 Hardware Test App 并切换启动入口。

### 检查点 2：两列布局与动态 Registry

- 按 Registry 顺序渲染当前页，禁止用 App ID 分支或固定业务入口数组生成菜单。
- 在 160 × 128 屏幕内实现标题区、2 × 2 入口区和页码／状态区，文字不得明显溢出或重叠。
- 对 0、1、2、3、4、5、7、16 个 App 的数量边界进行静态或自动化验证。
- 名称过长时使用确定的截断、滚动或裁剪策略，不能破坏相邻入口布局。

预期结果：新增静态注册 App 无需修改 Launcher 业务逻辑即可自动出现，超过 4 个入口时页数正确。

### 检查点 3：焦点、分页与 Navigation 接入

- 实现左右同一行移动、上下同列移动、末页缺项回退和所有边界不循环语义。
- 焦点跨过每页边界时更新可见入口和页码；返回上一页时索引保持准确。
- A 键只通过 Navigation 打开当前 App；打开失败不改变 Launcher 稳定状态。
- App 返回后验证原焦点、页码、Launcher 根对象和 screen 子对象数量保持不变。
- 根页面 B 键保持幂等，不触发 App 回调或对象重建。

预期结果：焦点状态、显示页和实际打开的 App 始终一致，多轮进入／返回无对象泄漏。

### 检查点 4：开发自测与真实按键路径

- 新增仅在 `XIAOMIAO_LAUNCHER_SELF_TEST=ON` 时编译的 7 个静态测试 App 和自测入口。
- 自动断言空 Registry、重复创建、页数、初始焦点、移动边界、末页缺项、打开失败、创建／销毁对象基线和多轮 open/back。
- 实机至少完成：四方向遍历第一页、向下跨到第二页、末页单项边界、A 打开指定 App、B 返回并恢复焦点、根页面 B 幂等，以及连续 3 轮打开／返回。
- 全部通过后输出唯一成功标记 `LAUNCHER_SELF_TEST: PASS`；任一断言失败输出 `LAUNCHER_SELF_TEST: FAIL` 和具体条件并停止验收。

预期结果：动态入口、焦点移动、分页、Navigation 进入／返回和对象释放均有自动断言及实机按键证据。

## 失败路径与处理要求

- Registry 为空、索引越界或目标描述为空：不得解引用无效指针；保持当前稳定界面并记录明确错误。
- `xiaomiao_navigation_open()` 失败：不改变焦点、页码和 Launcher 对象；不得通过重建页面掩盖错误。
- App 返回后焦点丢失、页码变化或 Launcher 根对象被删除：保持 Goal 未完成，修正 group／对象所有权和恢复逻辑。
- 末页缺项导致焦点落到不存在入口：保持 Goal 未完成，不通过创建不可见占位 App 绕过。
- 多轮分页或进入／返回后 screen 子对象数量增长：视为对象泄漏，定位并修复后重新由人工验证。
- 名称溢出遮挡相邻入口或焦点反馈无法辨认：调整确定性布局，不以测试人员“能猜到当前项”作为通过依据。
- 自测宏污染普通固件或多个自测入口同时生效：修正 CMake 和预处理互斥关系，不依赖构建顺序碰巧通过。
- 普通 Dashboard 回归失败：保持节点 3 未完成，先定位 Launcher 接入对启动分支、按键或 LVGL 的影响。
- 人工无法完成编译、烧录或实机验证：只记录 Agent 静态检查结果，对应项标记“未验证”，不得将节点 3 标记完成。

### 实现要点（对应已确定决策）

- Launcher 不复制 App 列表，创建与翻页时按 `xiaomiao_app_registry_count()/get_at()` 读取（决策 2）。
- 页码由 `s_focus / 4` 推导；每页固定 4 个卡片槽位，翻页时复用槽位、仅改内容与焦点样式，同页移动只重绘受影响的两个入口，不销毁重建（决策 3、6）。
- 焦点移动规则集中在 `launcher_next_index()`：左右限本行且行首／行尾不循环；上下同列 ±2 可跨页；下键在右列越界时回退到该行左侧有效入口，其余越界保持焦点（决策 5）。
- A 键仅调用 `xiaomiao_navigation_open()`；失败时保持焦点、页码与全部对象，输出含 App ID 与错误码的日志（决策 7）。
- Launcher 根对象与 Navigation 内容根同在活动 screen，进入／返回不重建 Launcher（决策 8）。
- 根页面 B 调用 `xiaomiao_navigation_back()`，幂等且无回调；App 打开期间的按键由 Launcher 统一路由，B 返回、方向键与 A 忽略（决策 9）。
- 空 Registry 显示 `no apps registered` 与 `0/0`，所有按键为空操作且不创建 Navigation 内容根（决策 10）。
- `icon` 非空时以文本显示，为空时显示统一占位条，无外部资源依赖（决策 11）。
- `destroy()` 先 `lv_group_remove_obj()` 再 `lv_obj_delete()`，释放全部子对象并清零内部引用；App 打开期间返回 `ESP_ERR_INVALID_STATE`（决策 12）。

### 自测设计

- 自动断言：未创建／空 group／重复销毁、空 Registry 全按键无副作用、重复创建、0／1／2／3／4／5／7／16 个 App 时的初始焦点与页码、末项可达索引与页归属、越界移动不越界、完整方向移动表（含行首／行尾／顶行保持与末页缺项回退）、Manager 未初始化时的打开失败、App 打开期间 `destroy()` 被拒且状态不变、两轮 open/back 与根页面 B 幂等、screen 子对象基线恢复。
- 引导式按键路径：顶层状态条逐步提示需按的键，共 15 步方向遍历加 3 轮「A 打开 → B 返回 → B 幂等」，每次按键断言焦点与页码；结束后输出 `LAUNCHER_SELF_TEST: PASS`。
- 自测代码仅在 `XIAOMIAO_LAUNCHER_SELF_TEST=ON` 时编译，普通固件不包含测试 App 或状态条。

### 实现的取舍与已知边界

- Launcher 保存的状态：实现只保留自身根对象、页面对象引用与当前焦点索引，未额外保存 LVGL group 指针——`destroy()` 通过 `lv_group_remove_obj(s_root)` 按对象自身的 group 关系移除，group 参数无需留存。这是对决策 4 的收窄（只保存更少的东西），不影响“不复制 Manager 当前 App 状态”的约束。
- 页数验证方式：公开接口未暴露总页数，自测通过“末项索引归属页 == (count-1)/4”以及越界后页归属不变来间接验证分页正确性；页码文本本身由人工在屏幕上确认。
- 测试 App 数量：为满足检查点 2 的 0／1／2／3／4／5／7／16 数量边界，自测定义了 16 个静态 App 描述，主流程只注册前 7 个（覆盖两页、偶数行、末页单项），其余仅用于数量边界循环。决策 14 的“至少 7 个”得到满足，但描述数量多于 7 个。
- B 键归属：节点 3 的测试 App 不向 LVGL group 注册自己的可聚焦对象，因此 App 打开期间按键仍落在 Launcher 根对象上。Launcher 因此在“App 打开”状态下只把 B 转发给 `xiaomiao_navigation_back()`，并忽略方向键与 A。节点 4 的 Hardware Test App 若自行注册可聚焦对象与按键处理，将自然接管输入，这里的转发分支不再生效；届时需要复核该分支是否需要调整。
- 自测状态条：引导式提示条挂在 `lv_layer_top()` 上，只在 `XIAOMIAO_LAUNCHER_SELF_TEST=ON` 时编译，普通固件不存在。
