## 目标与预期行为

新增独立的 `Settings` App，并通过统一 App Registry 注册到普通固件。Launcher 按 Games → PC Monitor → Tools → Settings → Hardware Test 顺序显示 5 个入口：第 1 页保持 2 列 × 2 行满页，第 2 页显示 Hardware Test，从而首次在普通固件中实际使用 Launcher 分页能力。

Settings 首页固定提供 `Wi-Fi`、`Display`、`Sound`、`System` 四个菜单项。上下键移动焦点，A 进入所选详情页；B 在详情页返回 Settings 首页，B 在 Settings 首页返回 Launcher。四个详情页只显示当前真实能力状态与后续节点，不提供无后端、无法生效或无法持久化的开关和数值。

本节点只建立 Settings UI、两级导航和五入口分页回归基线。不得提前实现 Settings Service、NVS、Wi-Fi、显示参数控制、Audio Service 或任何设置持久化；不得为 Settings 创建独立 FreeRTOS Task。

## 背景与文件入口

- `docs/xiaomiao_firmware_v0.1_design.md` 第 6 节规定 Settings 第一版建立 Wi-Fi、Display、Sound、System UI 骨架；第 15 节要求未实现选项明确标记状态。
- `main/apps/tools/` 已验证单列菜单、详情页、LVGL 默认 group、B 按下锁存与释放解锁、Navigation 内容根所有权。Settings 沿用已经验证的交互语义，但不跨模块调用 Tools 私有实现。
- `main/main.c` 的 `launcher_boot()` 当前按 Games → PC Monitor → Tools → Hardware Test 注册 4 个 App；注册顺序就是 Launcher 显示顺序和焦点索引。
- `main/framework/xiaomiao_launcher.c` 每页固定 4 个入口，已有动态分页逻辑。注册 5 个 App 后索引固定为 Games 0、PC Monitor 1、Tools 2、Settings 3、Hardware Test 4；Settings 仍在第 1 页，Hardware Test 移到第 2 页。
- 当前 Launcher 的跨页规则决定：索引 2 向下到索引 4；索引 3 向下也落到索引 4；索引 4 向上回到索引 2。该行为属于现有通用导航规则，本节点只验证，不为 Settings 或 Hardware Test 增加特判。
- `main/framework/xiaomiao_navigation.c` 在 App `open` 前创建内容根，在 App `close` 后统一删除内容根及其全部子对象。
- Settings Service 与 NVS 尚不存在，设计文档也未确定具体设置字段、默认值和数据结构；节点 8 不得通过 UI 控件提前锁定节点 9 的配置模型。
- Wi-Fi Service 计划在节点 10 实现，Audio Service 计划在节点 12 实现。详情页只能陈述能力不可用，不能显示 `Connected`／`Disconnected`、音量或开关等虚假运行状态。

## 已确定的实现决策

1. Settings 放在 `main/apps/settings/`，沿用现有业务 App 目录结构；不把菜单或详情页实现写入 `main/main.c`。
2. `xiaomiao_settings.c` 内定义固件全生命周期有效的 `static const xiaomiao_app_t` 描述；头文件只暴露 `const xiaomiao_app_t *xiaomiao_settings_app(void)`。
3. App 描述固定为 `id = "settings"`、`name = "Settings"`、`icon = LV_SYMBOL_EDIT`、`init = NULL`。当前 LVGL 9.5 的 `lv_symbol_def.h` 已确认 `LV_SYMBOL_EDIT` 存在；不复用 Hardware Test 的 `LV_SYMBOL_SETTINGS`，避免 Launcher 上两个入口使用相同齿轮图标。
4. 普通固件注册顺序固定为 Games、PC Monitor、Tools、Settings、Hardware Test。任一注册失败都记录 App ID 与错误码并终止后续 Manager／Launcher 初始化，不跳过失败 App。
5. Settings `open` 只在 `xiaomiao_navigation_app_root()` 下创建一个全屏输入根和其子对象，不创建、切换或删除全局 screen，也不删除 Navigation 内容根。
6. 内部视图使用私有枚举表示 `MENU`、`WIFI`、`DISPLAY`、`SOUND`、`SYSTEM`。切换视图时只清理并重建 Settings 自己的内容容器，不删除输入根或 Navigation 内容根。
7. 菜单固定为 `Wi-Fi`、`Display`、`Sound`、`System`，初始焦点为 `Wi-Fi`。上下键按边界停止、不循环；A 进入当前详情页；左右键无操作。
8. 四行菜单必须适配 160 × 128：标题、四个焦点行和底部提示均使用固定坐标与明确尺寸，文字超长时确定性截断，不滚动、不越界。
9. Settings 根对象加入 `lv_group_get_default()` 返回的 group 并取得焦点，通过单一 `LV_EVENT_KEY` 回调处理上下、A、B。Settings 不依赖 Launcher，不访问 `main.c` 的私有输入变量。
10. B 沿用节点 7 已验证的“一次物理按压只执行一次动作”语义：首次 `LV_KEY_ESC` 设置锁存并执行一次后退，长按重复事件全部忽略；一个 20 ms LVGL timer 检测 keypad 已释放后清除锁存。菜单页关闭动作从对象按键回调延后到 timer 中执行，避免在焦点对象自己的回调里删除对象。
11. `open` 通过 LVGL indev 枚举查找 keypad。默认 group、keypad 或 B 解锁 timer 缺失时记录错误，不读取 GPIO 或引用 `main.c` 私有状态绕过。
12. 详情页只呈现以下真实能力状态，不创建可交互控件：
    - Wi-Fi：Wi-Fi Service 不可用，计划由节点 10 实现。
    - Display：设置后端不可用，具体字段和语义留待节点 9 定义。
    - Sound：Audio Service 不可用，计划由节点 12 实现。
    - System：设置后端不可用，具体字段和语义留待节点 9 定义。
13. 状态页不得把“服务未实现”表述为设备错误，也不得承诺节点 9 尚未定义的亮度、休眠、主题、音量、恢复出厂等功能。
14. `close` 顺序固定为：删除 B 解锁 timer、从 group 移除 Settings 输入根、清空 indev／对象／视图／焦点／锁存引用。Navigation 在回调返回后删除内容根及全部子对象。
15. `open`／`close` 日志记录活动 screen 子对象数量；视图切换只记录调试级必要信息，不为每次方向键制造大量日志。
16. 节点 1～3 的三个 self-test 构建不注册真实 Settings App，继续使用各自测试数据；普通固件才注册 5 个真实 App。
17. ESP-IDF 编译、`set-target`、烧录、串口监视和目标板按键／显示验证全部由人工执行。Agent 只实施源码与文档修改、执行静态检查、提供命令并复核人工证据。

## 预期接口与内部状态

```c
#pragma once

#include "framework/xiaomiao_app.h"

const xiaomiao_app_t *xiaomiao_settings_app(void);
```

建议的内部状态仅限 `xiaomiao_settings.c`：

```c
typedef enum {
    SETTINGS_VIEW_MENU = 0,
    SETTINGS_VIEW_WIFI,
    SETTINGS_VIEW_DISPLAY,
    SETTINGS_VIEW_SOUND,
    SETTINGS_VIEW_SYSTEM,
} settings_view_t;
```

- 静态 App 描述访问接口不分配内存，调用方不得修改或释放返回值。
- App 内只保留输入根、内容容器、菜单行、keypad、B 解锁 timer、当前视图、菜单索引和 B 锁存等最小状态。
- 不提供跨模块设置 API，不定义持久化结构；节点 9 应根据独立 Goal 决定 Service 接口、默认值、NVS schema 与恢复策略。

## 失败路径与处理要求

- Settings 描述为空、ID 重复或注册失败：不得在缺失 Settings 的情况下继续作为成功启动；记录 App ID 和错误码，保持节点未完成。
- 注册顺序不是 Games → PC Monitor → Tools → Settings → Hardware Test：修正 Registry 顺序，不在 Launcher 内增加排序规则。
- Navigation 内容根为空：不得改用 `lv_screen_active()` 创建页面；记录错误并保留可诊断状态。
- 默认 group、keypad 或 B 解锁 timer 缺失：不得读取 GPIO 或依赖 `main.c` 私有变量绕过；记录错误，保持节点未完成。
- 详情页按住 B 连续返回两层：视为阻塞性输入缺陷，必须修复锁存和释放检测，不通过延长固定防抖时间掩盖。
- Settings 关闭后 group 保留已删除对象、timer 继续运行或 indev 引用继续被访问：视为阻塞性生命周期缺陷。
- 第 2 页空槽可聚焦／打开、焦点索引越界、跨页后页码错误或 Hardware Test 返回到错误页：视为阻塞性 Launcher 分页回归；先保留复现证据，再判断是否需要另行授权修改通用 Launcher。
- 任一详情页出现可操作开关、硬编码设置值、`Connected`／`Disconnected`、音量或“已保存”提示：视为真实性和范围缺陷，移除相关实现。
- 出现 `nvs_*`、`esp_wifi_*`、LEDC、GPIO、蜂鸣器、背光或其他硬件／Service 调用：视为越过节点边界，移除相关实现。
- 详情页文字溢出、四行菜单挤压、关键状态不可见或焦点不可辨识：视为 UI 验收失败，根据实机证据修正布局。
- Settings 内方向键影响 Launcher 焦点，或关闭后 Launcher 不能恢复按键：视为 input group 所有权缺陷，不在 Launcher 中增加 Settings 特判。
- 既有 App 的索引、B 语义、页面内容或 Hardware Test 15 页可达性回归：保持节点未完成并定位注册、焦点或生命周期问题。
- 人工无法完成编译、烧录或实机验证：只记录静态结果，对应项标记“未验证”，不得将节点 8 标记完成。
