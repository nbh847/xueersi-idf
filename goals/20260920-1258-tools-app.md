## 目标与预期行为

新增独立的 `Tools` App，并通过统一 App Registry 注册到普通固件。Launcher 按 Games → PC Monitor → Tools → Hardware Test 顺序显示 4 个入口，正好占满第 1 页的 2 列 × 2 行网格。

Tools 首页提供 `Wi-Fi`、`System Info`、`About` 三个菜单项：上下键在菜单项之间移动焦点，A 进入所选详情页；B 在详情页返回 Tools 首页，B 在 Tools 首页返回 Launcher。System Info 使用只读 ESP-IDF API 显示真实芯片、CPU 配置、Flash、PSRAM、ESP-IDF 和固件版本；About 显示项目及作者来源；Wi-Fi 在节点 10 前如实显示 Service 不可用，不伪造“已连接”或“未连接”状态。

本节点建立首个带 App 内菜单和两级返回语义的独立业务 App。不得提前实现 Wi-Fi 初始化、扫描、连接、重连、配置持久化或 Wi-Fi Service，也不得为 Tools 创建独立 FreeRTOS Task。

- `main/main.c` 的 `launcher_boot()` 当前按 Games → PC Monitor → Hardware Test 注册 3 个 App；注册顺序就是 Launcher 枚举、显示与焦点索引顺序。
- `main/framework/xiaomiao_launcher.c` 每页固定 2 列 × 2 行。新增 Tools 后索引为 Games 0、PC Monitor 1、Tools 2、Hardware Test 3，仍全部位于第 1 页。
- `main/framework/xiaomiao_navigation.c` 在 App `open` 前创建内容根，在 App `close` 后统一删除内容根及全部子对象。
- `main/main.c` 创建并设定唯一 LVGL 默认 group；Tools 可用 `lv_group_get_default()` 取得 UI 输入 group，无需依赖 `main.c` 私有变量或 Launcher 接口。
- LVGL 9.5 keypad 对 `LV_KEY_ESC` 只在按下和长按重复阶段派发 `LV_EVENT_KEY`，释放时不派发对象事件。若详情页直接在每个 ESC 事件上后退，按住 B 会先返回菜单，再因重复事件退出 App；必须有独立的按下锁存与释放解锁机制。
- Hardware Test 已显示部分系统信息，但实现位于 `main/main.c` 的静态函数和硬件 Dashboard 页面中。Tools 不跨模块调用这些私有函数，也不为复用而搬迁 Dashboard。

## 已确定的实现决策

1. Tools 放在 `main/apps/tools/`，沿用现有业务 App 目录结构；不把菜单或详情页实现写入 `main/main.c`。
2. `xiaomiao_tools.c` 内定义固件全生命周期有效的 `static const xiaomiao_app_t` 描述；头文件只暴露 `const xiaomiao_app_t *xiaomiao_tools_app(void)`，不暴露 LVGL 对象、内部状态或生命周期回调。
3. App 描述固定为 `id = "tools"`、`name = "Tools"`、`icon = LV_SYMBOL_LIST`、`init = NULL`。本仓库锁定的 LVGL 9.5 未定义 `LV_SYMBOL_WRENCH`；`LV_SYMBOL_LIST` 已在 `lv_symbol_def.h` 及内置 symbol 字形范围中确认存在，用于表达工具菜单且不与 Hardware Test 的 `LV_SYMBOL_SETTINGS` 重复。
4. 普通固件注册顺序固定为 Games 第一、PC Monitor 第二、Tools 第三、Hardware Test 第四。任一注册失败都记录 App ID 与错误码并终止后续 Manager／Launcher 初始化，不跳过失败 App，也不回退到旧 Dashboard。
5. Tools `open` 只在 `xiaomiao_navigation_app_root()` 下创建一个全屏根容器和其子对象，不创建、切换或删除全局 screen，也不删除 Navigation 内容根。
6. Tools 内部视图使用私有枚举表示 `MENU`、`WIFI`、`SYSTEM_INFO`、`ABOUT`。切换视图时只清理并重建 Tools 自己的内容容器，不删除输入根或 Navigation 内容根。
7. 菜单固定为 `Wi-Fi`、`System Info`、`About` 三项，初始焦点为 `Wi-Fi`。上下键按边界停止、不循环；A 进入当前详情页；左右键无操作。
8. Tools 根对象加入 `lv_group_get_default()` 返回的 group 并取得焦点，通过单一 `LV_EVENT_KEY` 回调处理上下、A、B。业务 App 只依赖 LVGL group，不引用 Launcher，不访问 `main.c` 的 `s_input_group`。
9. B 使用一次按下只执行一次动作的锁存：首次 `LV_KEY_ESC` 设置锁存并执行“详情页 → 菜单”或“菜单 → Navigation 返回”；长按重复产生的后续 ESC 事件全部忽略。一个 20 ms LVGL timer 只在锁存期间检查 keypad indev 状态，检测到 `LV_INDEV_STATE_RELEASED` 后清除锁存。该 timer 在 `close` 中先删除，不创建 FreeRTOS Task。
10. `open` 通过 `lv_indev_get_next()` 查找 `LV_INDEV_TYPE_KEYPAD`，并保存只在 App 打开期间有效的 indev 引用。默认 group、keypad indev 或 B 解锁 timer 缺失时记录错误；不得退回到直接读取 GPIO。输入基础设施不完整时节点保持未完成。
11. 菜单页使用 160 × 128 单列布局：顶部标题 `Tools`，中部三行菜单项，当前项使用确定性高亮，底部显示 `A Open  B Back`。不依赖外部资源。
12. 详情页顶部显示页面名，内容区显示只读信息，底部显示 `B Back`。详情页不加入额外 group 对象，避免 LVGL 自动焦点移动与 App 私有焦点状态产生双重来源。
13. System Info 每次进入详情页时采集一次，不创建周期刷新：
    - 芯片：`esp_chip_info()`，显示实际芯片 family 和核心数，不硬编码 `ESP32-D0WD` 封装名。
    - CPU：`CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ`，明确表示当前构建配置频率，不使用私有时钟 API。
    - Flash：`esp_flash_get_size(NULL, &bytes)`，成功时按 MiB 显示，失败时显示 `Unknown` 并记录错误码。
    - PSRAM：`heap_caps_get_total_size(MALLOC_CAP_SPIRAM)`，按 MiB 显示；返回 0 时显示 `None`，不硬编码 8 MB。
    - ESP-IDF：`esp_get_idf_version()`。
    - 固件：`esp_app_get_description()->version`，显示实际构建版本，不硬编码 `v0.1`。
14. System Info 只使用只读通用系统 API，不初始化设备、不改变时钟或内存配置。所有格式化缓冲区为固定容量，使用 `snprintf`，文本超长时确定性截断且不得越界。
15. Wi-Fi 详情页固定显示 `Wi-Fi Service`、`Unavailable`、`Implemented in node 10`。此处“Unavailable”是真实能力状态，不等价于网络断开；节点 10 接入 Service 后再替换为真实状态查询。
16. About 详情页至少显示 `Xiaomiao`、实际固件版本、`ZYoungInc` 和仓库标识 `nbh847/xueersi-idf`；长文本使用明确宽度和换行，不从网络或文件系统加载。
17. `close` 顺序固定为：删除 B 解锁 timer、从 group 移除 Tools 输入根、清空 indev／对象／视图／焦点／锁存引用。Navigation 在回调返回后删除内容根及全部子对象。
18. `open`／`close` 日志记录活动 screen 子对象数量；视图切换只记录调试级必要信息，不为每次方向键制造大量日志。
19. 节点 1～3 的三个 self-test 构建不注册真实 Tools App，继续使用各自测试数据；普通固件才注册 4 个真实 App。
20. ESP-IDF 编译、`set-target`、烧录、串口监视和目标板按键／显示验证全部由人工执行。Agent 只实施源码与文档修改、执行静态检查、提供命令并复核人工证据。

## 预期接口与内部状态

```c
#pragma once

#include "framework/xiaomiao_app.h"

const xiaomiao_app_t *xiaomiao_tools_app(void);
```

建议的内部状态仅限 `xiaomiao_tools.c`：

```c
typedef enum {
    TOOLS_VIEW_MENU = 0,
    TOOLS_VIEW_WIFI,
    TOOLS_VIEW_SYSTEM_INFO,
    TOOLS_VIEW_ABOUT,
} tools_view_t;
```

- 静态 App 描述访问接口不分配内存，调用方不得修改或释放返回值。
- App 内只保留输入根、内容容器、菜单高亮对象、keypad indev、B 解锁 timer、当前视图、菜单索引和 B 锁存等最小状态。
- 不提供跨模块的 System Info、Wi-Fi 或 About API；节点 10 若需要接入 Wi-Fi 状态，应先另立 Goal 定义 Service 边界。

## 失败路径与处理要求

- Tools 描述为空、ID 重复或注册失败：不得在缺失 Tools 的情况下继续作为成功启动；记录 App ID 和错误码，保持节点未完成。
- 注册顺序不是 Games → PC Monitor → Tools → Hardware Test：修正 Registry 顺序，不在 Launcher 内增加排序规则。
- Navigation 内容根为空：不得改用 `lv_screen_active()` 创建页面；记录错误并保留可诊断状态。
- 默认 group 或 keypad indev 缺失：不得读取 GPIO 或依赖 `main.c` 私有变量绕过；记录错误，保持节点未完成。
- B 解锁 timer 创建失败：不得以无防重复的两级 B 逻辑交付；记录错误，保持节点未完成。
- 详情页按住 B 连续返回两层：视为阻塞性输入缺陷，必须修复锁存和释放检测，不通过延长固定防抖时间掩盖。
- Tools 关闭后 group 保留已删除对象、timer 继续运行或 indev 引用继续被访问：视为阻塞性生命周期缺陷。
- System Info 使用硬编码 Flash／PSRAM／固件版本，或显示值与实际构建不一致：视为真实性缺陷，改用已确定的只读来源。
- Flash 读取失败：显示 `Unknown` 并记录错误码，不崩溃、不显示猜测容量。
- PSRAM 总量为 0：显示 `None`，不把缺失能力视为启动错误。
- Wi-Fi 页面显示 `Connected`／`Disconnected`，或出现 `esp_wifi_*`／网络调用：视为越过节点 10 边界，移除相关实现。
- 详情页文字溢出、关键字段被省略、菜单焦点不可辨识：视为 UI 验收失败，保持节点未完成并根据实机证据修正布局。
- Tools 内方向键影响 Launcher 焦点，或关闭后 Launcher 不能恢复按键：视为 input group 所有权缺陷，不在 Launcher 中增加 Tools 特判。
- Hardware Test 的索引仍按 2 判断、返回焦点错误、短按 B 变为退出或长按 B 失效：视为阻塞性回归。
- 多轮后 screen 子对象数量增长、open／close 不配对、重复返回、崩溃或花屏：保持节点未完成，定位内容根、timer、group 或引用清理问题。
- 人工无法完成编译、烧录或实机验证：只记录静态结果，对应项标记“未验证”，不得将节点 7 标记完成。

### 与施工设计的差异

1. **`main/CMakeLists.txt` 增加 `esp_app_format` 到 `PRIV_REQUIRES`**（超出“只把 Tools 源文件纳入 `main` 组件”的字面范围，属必要补充）。原因：决策 13 要求固件版本取自 `esp_app_get_description()`（声明于 `esp_app_format/include/esp_app_desc.h:55`），而从 `build/compile_commands.json` 核实 `main.c` 的编译命令**不含** `esp_app_format` 头文件路径，原样 include 必然编译失败。该组件是 ESP-IDF 自带组件，不新增第三方依赖、不改变任何版本，故按最小改动补齐而不是改用硬编码版本或绕过。
2. **菜单页的 App 关闭动作延后到 B 解锁 timer 中执行**，而不是在按键回调里直接调用 `xiaomiao_navigation_back()`。原因：B 的按键事件派发目标就是 Tools 根对象，而 `navigation_back()` 会经 `close` 回调由 Navigation 删除该对象的父内容根；即使 LVGL 9.5 有 `lv_event_mark_deleted()` 保护（`lv_obj.c:606`、`lv_event.c:323`），在焦点对象自己的回调里删除它仍是不必要的风险。timer 回调运行在 `lv_timer_handler()` 中，与节点 4 把 B 动作放到 LVGL 循环执行的既有做法一致；`lv_timer.c:368` 明确支持 timer 在自身回调内被删除，`close` 中的 `lv_timer_delete()` 因此安全。详情页 → 菜单的切换仍直接在回调内重建内容容器（派发目标根对象不受影响，与 Dashboard `ui_key_cb` 重建页面同构）。
3. 其余按施工设计执行：`id=tools`、`name=Tools`、`icon=LV_SYMBOL_LIST`、`init=NULL`；菜单固定三项且初始焦点为 `Wi-Fi`；上下键边界停止、左右无操作；详情页不加入额外 group 对象；`Wi-Fi` 页固定显示服务不可用；System Info 每次进入采集一次、无周期刷新；`close` 按“删 timer → 移出 group → 清空引用”顺序执行。
