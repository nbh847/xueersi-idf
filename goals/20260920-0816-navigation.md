## 目标与预期行为

在不改变普通固件现有 15 页 Hardware Dashboard 启动和操作行为的前提下，在 App Manager 之上建立统一 Navigation 层。Navigation 负责打开指定 App、处理返回、维护 App 内容根对象，并保证返回后当前 App 状态和 LVGL 对象恢复到进入前的根页面状态。

本 Goal 使用开发自测 App 验证 `A` 进入、`B` 返回和对象释放，但不实现正式 Launcher、焦点网格、分页或任何正式业务 App。

- 当前普通固件仍由 `main/main.c` 的 `lvgl_task()` 直接创建 Hardware Dashboard。

## 已确定的实现决策

1. Navigation 代码放在 `main/framework/`，继续属于现有 `main` 组件，不创建新的顶层组件。
2. Navigation 不保存第二份当前 App 指针；`xiaomiao_app_manager_current()` 仍是当前 App 状态的唯一来源。Manager 当前 App 为空表示位于根页面。
3. Navigation 提供最小接口：按 ID 打开 App、返回根页面、查询当前 App，以及获取当前 App 的 LVGL 内容根对象。具体命名在实现时保持 `xiaomiao_navigation_*` 前缀。
4. Navigation 在调用 `xiaomiao_app_manager_open()` 前创建一个覆盖活动屏幕的 App 内容根对象。App 的 `open` 回调只能在该根对象下创建界面，不得自行创建或切换全局 screen。
5. App 的 `close` 回调负责停止自身定时器、事件和非 LVGL 资源，但不得删除 Navigation 持有的内容根对象。Navigation 在 `close` 回调完成后统一删除该根对象；删除父对象必须同时释放全部子对象。
6. 打开失败时，Navigation 必须删除本次临时创建的内容根对象，并保持原有当前 App 和根页面不变；不得留下不可见对象或半打开状态。
7. 当前 App 未关闭时不允许直接打开另一个 App；切换必须先返回根页面，再打开目标 App。
8. 根页面按 `B` 为幂等空操作，返回 `ESP_OK`，不重复执行 App `close` 回调。
9. Navigation API 仅能在现有 LVGL Task 中调用。本节点不实现线程安全，不新增 Task、队列或锁。
10. Navigation 自测使用独立 CMake 选项 `XIAOMIAO_NAVIGATION_SELF_TEST=ON`；默认关闭，且不得改变普通固件的启动日志和 Dashboard 行为。
11. 正式 Launcher 尚未实现时，自测构建使用最小根页面和测试 App 验证进入、返回及对象释放；该测试页面不得进入普通固件。
12. ESP-IDF 编译、`set-target`、烧录、串口监视和目标板按键验证全部由人工执行。Agent 只提供命令、执行静态检查并复核人工提交的输出和结果，不主动运行构建或设备操作命令。

## 预期接口语义

接口名称可以在实现时按现有代码风格微调，但行为必须保持一致：

```c
esp_err_t xiaomiao_navigation_open(const char *app_id);
esp_err_t xiaomiao_navigation_back(void);
const xiaomiao_app_t *xiaomiao_navigation_current(void);
lv_obj_t *xiaomiao_navigation_app_root(void);
```

- `open(NULL)` 或空 ID：返回 `ESP_ERR_INVALID_ARG`，不创建对象。
- App Manager 尚未初始化：返回 `ESP_ERR_INVALID_STATE`，不留下内容根对象。
- App 不存在：返回 `ESP_ERR_NOT_FOUND`，不留下内容根对象。
- 已有当前 App：返回 `ESP_ERR_INVALID_STATE`，当前 App 和内容根对象保持不变。
- 打开成功：App `open` 回调执行一次，当前 App 与内容根对象均非空。
- `back()`：先执行 App `close`，再删除内容根对象，最后回到当前 App 为空的根页面状态。
- 根页面调用 `back()`：返回 `ESP_OK`，不执行回调、不创建或删除对象。

## 失败路径与处理要求

- 内容根创建失败：返回 `ESP_ERR_NO_MEM`，不得调用 App `open`，当前状态保持在根页面。
- Manager 打开失败：删除临时内容根，并原样返回 Manager 错误。
- App 在 `open` 中绕过 Navigation 根对象创建全局 UI：视为接口违约，验收不通过，不通过额外清理逻辑掩盖。
- App 在 `close` 中删除 Navigation 根对象：视为所有权违约，修正 App 后再验收，不增加双重删除兼容层。
- 返回后仍有 App 根对象、当前 App 非空或根页面子对象数量未恢复：保持 Goal 未完成，定位生命周期或对象所有权问题。
- 重复进入或返回导致回调次数错误：保持 Goal 未完成，不通过放宽断言绕过。
- 自测构建污染普通固件：Agent 检查 CMake option、编译宏和配置；由人工使用全新 `.tmp/` 目录复现并提交结果。
- Dashboard 回归失败：停止节点 3，先定位 Navigation 接入对按键、LVGL Task 或默认启动链的影响。
- 人工无法完成编译、烧录或实机按键验证：可以记录 Agent 静态检查结果，但对应项必须标记为“未验证”，不得将节点 2 标记完成。

### 编译失败记录与修复（2026-09-20）

- 首版实现在 `app_main()` 中用两个独立 `#if` 块并在自测块末尾 `return`，普通路径未被条件编译包裹。Navigation 自测构建下自测块与普通路径在同一函数作用域重复定义 `io_handle`、`display`、`group`、`callbacks`、`tick_timer_args`、`tick_timer`、`ret`，共 7 个 redefinition 编译错误（人工首次自测构建发现）。
- 根因：三个启动形态（普通 / Framework 自测 / Navigation 自测）本就互斥，却未用条件编译的互斥结构表达，属于实现结构错误而非环境问题。

### 第三次失败：实机自测断言捕获 open 回调根对象缺失（2026-09-20 09:37）

- 现象：烧录后自测固件启动链正常（LCD/LVGL/按键初始化、`Navigation self test start`），但自动断言在 `check_open_back_cycle` 首次成功 open 即失败：`NAVIGATION_SELF_TEST: FAIL app root available in open (root != NULL)`，`test_app_open`（selftest.c:52）断言 `xiaomiao_navigation_app_root() == NULL` 并 abort。
- 根因：`xiaomiao_navigation_open()` 初版把 `s_app_root = root` 放在 `xiaomiao_app_manager_open()` 成功之后（事务式提交），但 Manager 在其内部**同步执行 App `open` 回调**，回调经 `xiaomiao_navigation_app_root()` 读 `s_app_root` 时仍为 NULL。实现违背了 Goal 决策 4 与头文件声明的契约（回调可在内容根下创建界面）。
- 修复：`s_app_root = root` 提前到 Manager 调用之前；Manager 失败路径中先将 `s_app_root` 置回 NULL 再删除临时根对象。所有失败路径“不留对象”语义不变（`git diff --check` 通过）。
- 教训：内容根的“发布”时点必须早于任何会读取它的回调，提交式赋值不能横跨同步回调边界。该缺陷由开发自测首轮自动断言捕获，验证了自测设计的价值。
